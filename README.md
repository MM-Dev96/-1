# Nexus — AI Workspace

مساحة عمل عربية شخصية تحوّل فكرة التطبيق إلى ملفات تحليل وتنفيذ وبرومبت نهائي واحد. يشغّل Nexus المراحل وفق مخطط DAG حقيقي، ويحفظ المشاريع والنسخ محليًا في المتصفح.

## ما يعمل فعليًا

- محرك مهام داخل Node.js لا يحتاج PostgreSQL أو Redis أو عاملًا خارجيًا.
- تنفيذ متوازٍ مع احترام الاعتماديات، وإيقاف حقيقي بواسطة `AbortController`.
- حالات واضحة للمراحل: انتظار، تشغيل، اكتمال، فشل، حجب، تجاوز، وإلغاء.
- إعادة مرحلة محددة وكل المراحل التابعة لها فقط.
- عقد أحداث Socket.IO واحد مشترك بين الخادم والواجهة، مع polling احتياطي عند انقطاع الاتصال.
- ثلاثة أوضاع تشغيل: سريع، متوازن، وشامل، مع عدد الاستدعاءات المتوقع قبل البدء.
- محرر DAG مرئي يدعم الإضافة والحذف والربط وتحريك البطاقات وحفظ مواضعها.
- حفظ المشاريع والملفات والنسخ في IndexedDB، مع ترحيل مشاريع `app-store` القديمة.
- تصدير واستيراد نسخة JSON، وتنزيل المشروع أو البرومبت بصيغة Markdown.
- إنشاء نموذج HTML ثابت، ومعاينة ZIP أو مجلد مبني يحتوي `index.html`.
- تقييم البرومبت وتدقيق ملفات مختارة من خلال مدير المهام نفسه.
- واجهة RTL متجاوبة مع `dvh` وsafe areas وتقليل الحركة.

## التشغيل

المتطلبات: Node.js 20 أو أحدث.

```bash
npm install
cp .env.example .env
npm run dev
```

افتح:

```text
http://localhost:3000
```

يمكن وضع مفتاح Gemini في `.env`، أو إضافته من إعدادات التطبيق:

```dotenv
GEMINI_API_KEY=your_key_here
```

للتجربة المحلية دون استدعاء Gemini:

```dotenv
AI_PROVIDER=mock
```

## أوامر التحقق

```bash
npm run lint
npm test
npm run build
npm run check
```

`npm run check` يشغّل ESLint وTypeScript الصارم وVitest والبناء النهائي.

## البنية

```text
server.ts                    نقطة تشغيل Express وSocket.IO وVite
src/server/jobManager.ts     التنفيذ والإلغاء والاستئناف وإعادة المراحل
src/server/ai/               واجهة المزود وGemini والمزود التجريبي والبرومبتات
src/server/previewStore.ts   معاينات ثابتة مؤقتة في الذاكرة
src/shared/                  العقود ومخطط DAG والمراحل الافتراضية
src/lib/repository.ts        مستودع IndexedDB والهجرة والنسخ الاحتياطية
src/pages/                   المختبر والتقييم والإعدادات
src/components/              الغلاف والمحرر والمشاريع والمعاينة
```

## الاستعادة والاستمرارية

- عند انقطاع Socket.IO تستعيد الواجهة snapshot من `GET /api/jobs/:id`.
- إذا أعيد تشغيل الخادم وضاعت المهمة الموجودة في الذاكرة، استخدم «استئناف من المراحل المنجزة». ترسل الواجهة المخرجات المكتملة وتعيد تشغيل الباقي.
- المشروع الجاري يُحفظ تلقائيًا في IndexedDB؛ المخرجات مربوطة بـ`stage.id` وليس بترتيب المرحلة.

## حدود المعاينة

المعاينة الثابتة تشغّل HTML/CSS/JavaScript المبني فقط. إذا رفعت مصدر React أو Vite وفيه `package.json` دون `index.html` مبني، سيخبرك التطبيق أن المشروع يحتاج `build` بدل عرض نتيجة وهمية.

## Google AI Studio

بعد دمج فرع الإصلاح في GitHub:

1. افتح Build mode.
2. من زر إضافة الملفات `+` اختر **Import from GitHub**.
3. اختر المستودع والفرع المصحح.

AI Studio لا يسحب تلقائيًا التعديلات الخارجية إلى مساحة عمل مفتوحة قديمة. للحفاظ على المحادثة القديمة، أنشئ Checkpoint أولًا ثم ارفع ZIP للنسخة المصححة داخل المشروع.

## الاختبارات

تغطي اختبارات Vitest:

- اكتشاف الدورات والمراجع المفقودة في DAG.
- ترتيب الأحداث ومنع تطبيق الأحداث القديمة مرتين.
- التنفيذ المتوازي والحجب والإلغاء.
- حفظ IndexedDB وتصدير/استيراد JSON.
- اكتشاف المعاينة الثابتة مقابل المشاريع التي تحتاج build.
- health API وبدء المهام والتحقق من المدخلات.
